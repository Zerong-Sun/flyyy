# 地球渲染降温优化：六维验证与修复清单

日期：2026-08-10
范围：Godot 桌面版 60 FPS、机场 pin 投影、机场 pin MultiMesh 合批。

## 结论

三项需求均已完整落地。Apple M2 Pro 上静止新游戏界面的 Godot 进程 CPU
由约 31%–36% 降至约 7%–16%；真实窗口内已验证开始游戏、机场聚焦、航线绘制、
当前/选中机场标签与 pin 状态显示。内存仍约 0.82 GB，本次未处理数据集和 Label3D 池。

## 修复清单

- [x] 显式限制 60 FPS，并启用 VSync。
- [x] 机场 pin 批次统一关闭阴影投射。
- [x] 500 个独立 pin 节点和材质改为四状态 MultiMesh 与四份共享材质。
- [x] 拾取逻辑改用独立机场位置表，保持点击选择能力。
- [x] 重复构建时先从场景树移除旧节点，避免同帧短暂重复渲染。
- [x] 色盲模式切换后立即刷新共享材质与实例缩放。
- [x] 性能烟测解除发行版 60 FPS 上限，继续测量真实 CPU 余量。
- [x] 增加配置、批处理、共享资源和阴影状态回归断言。

## 验证记录

- `SmokePerf.gd`：构建 281 ms，CPU 基线 142.6 FPS，7.01 ms/帧，`SMOKE_PERF_OK`。
- `SmokeContent.gd`：`SMOKE_CONTENT_OK`。
- Python：133 passed，3 skipped（全量基线）；新增热优化专项测试另行执行。
- Expo：32 passed。
- 图形运行：Forward+ / Metal，Apple M2 Pro；开始游戏、选择 DXB、切换色盲模式后
  静止 CPU 约 7%–8%，多次启动采样范围约 7%–16%。

## 剩余风险

- 500 个 `Label3D` 仍在启动时创建，虽然通常隐藏，但会维持节点和内存开销。
- 4K 地球贴图与 Forward+ 未调整，低配设备仍需单独做 GPU/显存门禁。
- macOS CPU 采样不包含可直接对比的 GPU 功耗数值；发布前仍建议用 Godot Profiler
  和 Instruments 做 1080p、航线密集、长时间运行验证。
